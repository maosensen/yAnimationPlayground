# v0.7 AI 辅助动画生产管线

## 核心问题

AI 或 Coding Agent 怎样加速动画前期生产，同时避免提示词、生成决策和审查状态成为无法
复现、无法交接的黑箱？

## 对比实现

本实验没有比较模型厂商，而是比较两种生产组织方式：

1. 提示词直接生成实现代码，审查主要发生在最终页面或成片；
2. AI 先提交受 Schema 约束的 production draft，人批准故事板、资产与实现分工，再由
   确定性编译器生成下游产物。

最终采用第二种。模型能力会快速变化，但项目 ID、场景时间、资产引用、输出规格、人工
批准与 QA 规则是更稳定、也更值得迁移到 Studio 的契约。

## 测量数据

| 项目 | Signal Atlas 结果 |
|---|---|
| 人工输入 | 1 份 creative brief |
| AI / Agent 结构化输入 | 1 份 production draft |
| 编译产物 | 5 份：storyboard、assets、scaffold、QA、provenance |
| 场景 | 3 个连续场景，共 12 秒 |
| 实现目标 | Web 工作台 + Remotion |
| 输出规格 | 1920 × 1080、1080 × 1920 |
| 自动 QA | 10 条规则，参考样例 10/10 通过 |
| 受控失败 | 缺失资产引用，9/10 并阻断 |
| 契约测试 | 3 项：通过样例、确定性、失败检测 |
| 模型运行时依赖 | 0 |
| 参考横版成片 | H.264、30 FPS、12.053 秒、1,696,480 bytes |

测试耗时会受机器影响；本次 Node 内置测试运行约 85ms。更关键的指标是同一输入连续编译
得到相同 `ab5065bf114a…` bundle hash。

## 视觉与交互发现

- 工作台按五阶段组织，比直接展示 JSON 更容易判断“谁负责什么、何时可以继续”。
- 稳定 ID、文件名与动画内部 copy 保留英文；功能说明、参数解释、规则与结论全部在 UI
  层翻译为中文，底层 Agent 契约仍可保持英文。
- 五阶段导航在窄屏允许横向滚动，内容与 QA 侧栏会降为单列；不会强行把流程卡压缩到
  无法阅读。
- Remotion 直接消费同一 reference bundle，证明 scaffold 能进入真实运行时，而不是只停
  在文档层。

## 失败模式

### 只做 JSON Schema 校验

缺失资产 fixture 的结构完全合法，如果只验证字段和类型，它会错误进入实现。语义 QA
必须交叉检查 manifest 引用、时间线、规格覆盖与 review gates。

### 让模型填写“approved”即视为批准

字段无法证明真实责任主体。当前参考样例只模拟完成审查后的稳定输入；正式 Studio 必须在
自己的身份与权限系统中记录批准，再把结果投影到管线契约。

### 把模型 SDK 放进 Web 或 Remotion

这会让审查后的生产 bundle 依赖供应商、密钥和网络状态，也会污染客户端与渲染环境。
模型调用应该停在上游 adapter，运行时只读取固定产物。

### 生成文件不提交

CI 只能知道“今天能生成”，无法审查生成差异。source 与 generated 同时提交，并用
drift check 确认二者关系，才能形成可追溯交付。

## 技术结论

- 默认流程是 **human brief → structured AI draft → human gates → deterministic compiler →
  executable QA → runtime consumer**。
- JSON Schema 负责输入形状，语义 QA 负责跨文件事实，两者不能互相替代。
- AI 的价值主要在提出故事板、资产计划与实现分工候选；创意批准和发布判断仍由人负责。
- Playground 只验证可迁移契约。模型路由、协作、持久化、时间线编辑、云渲染与计费应在
  后续独立 Studio 仓库实现。

## 可复用候选

- `@yanimation/animation-pipeline` 的 v1 Schema 与编译器；
- provider-neutral production director prompt contract；
- stable ID、artifact hash 与 bundle provenance 格式；
- Schema + semantic QA + controlled failing fixture 的测试模式。

这些接口目前仍是仓库内部 `0.1.0`。跨仓发布、兼容策略与外部消费者验证属于 v0.9。
