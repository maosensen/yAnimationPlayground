# 可中断动画曲线 Studio

## 核心问题

Screen Studio 式连续 zoom / pan 的“丝滑”是否主要来自某一条
cubic-bezier，还是来自保存 position + velocity 的临界阻尼弹簧状态？

## 对比实现

- Spring：使用临界阻尼闭式解，omega 默认为 7.5s⁻¹，x、y、scale
  三个通道独立求值但共享同一参数；重定向时可继承当前速度。
- Bezier：使用最接近静态外观的
  cubic-bezier(0.25, 1, 0.3, 1)，每次重定向从当前值重新开始一段
  0% → 100% 的时间映射；它不消费 omega，只把比较时长匹配为 9 / omega。
- 两个实现消费同一组全景、左上、右侧和光标跟随目标，画面、目标时刻与
  调试操作保持一致。

## 测量数据

参考环境为本地 Next.js 16.3 开发页面、Chromium、1440×1000 与
390×844 CSS 视口。

| 指标 | 默认结果 |
|---|---|
| omega | 7.5s⁻¹ |
| 观察时间窗 | 9 / omega = 1.20s |
| Spring 到达 90% | 约 0.52s，占观察窗约 43% |
| 新增运行时依赖 | 0 |
| 数学门禁 | t=0 的位置/速度、90% 响应、长时间收敛、Bezier 两端点均通过 |
| 页面宽度 | 1440px 与 390px 均无横向溢出 |

实时舞台只在运动期间运行 requestAnimationFrame，画面每帧直接写入
transform/filter，React 遥测降频到约 20Hz，避免把每一帧送入组件渲染。

## 视觉与交互发现

- 单次播放时，弹簧和 expo-out 风格 Bezier 的位置曲线很接近，仅凭终点外观
  很难判断实现方式。
- 快速连续点击目标后，差异主要出现在速度曲线：Spring 可用当前 velocity
  作为下一段 v0；Bezier 必须重新计时，容易形成肉眼可感知的顿点。
- x、y、scale 使用同一 omega 后，镜头的位移和缩放更像一个整体；三个
  通道各自选择不同 duration/easing 会产生“画面先滑、缩放后追”的分离感。
- 减少动态效果模式下，舞台直接到达目标，但曲线和技术说明仍保留，避免删除
  实验信息。
- 移动端按单列排列两个舞台和参数，保留完整控制与曲线，没有依赖横向滚动。

## 失败模式

- 只观察 position 曲线会高估 Bezier 的等价程度；必须同时检查 velocity。
- 在动画进行中直接替换 omega 而不重新建立 segment，会改变已有闭式解并
  产生不连续；当前 Studio 将参数用于下一次目标事件。
- Bezier 重定向不是笼统的“速度归零”：本例曲线起始斜率为 4，重定向会
  重置为新曲线的起始速度；关键问题是它通常与打断前的瞬时速度不连续。
- 浏览器 blur() 只能作为速度大小的诊断近似，不是方向性 motion blur。
  正式视频管线应使用速度向量决定模糊方向和半径。
- 给 scale、x、y 分别配置曲线或时长，会破坏镜头运动的一体感。

## 技术结论

默认决策不是“所有动画都用弹簧”：

1. 已知起止点、不会被打断的短 UI 过渡继续使用语义化 Bezier。
2. 镜头跟随、拖拽、连续 zoom / pan 和任何需要中途改目标的运动，使用带
   position + velocity 的弹簧状态。
3. 确定性逐帧渲染优先使用临界阻尼闭式解；同一时间输入可直接得到同一画面，
   无需依赖前一帧数值积分。
4. 必须降级到 CSS 时，使用 cubic-bezier(0.25, 1, 0.3, 1) 或采样后的
   linear()，但不把静态近似宣传为具备速度继承。

## 可复用候选

- 临界阻尼 position / velocity 闭式解。
- omega 的语义档位：约 6 为舒缓，7.5 为默认，9 以上偏干脆。
- 跨通道镜头状态 { x, y, scale } + velocity。
- 基于速度向量的渲染器 motion-blur 适配接口。

这些候选目前只服务 Studio。等 Remotion、HyperFrames 或独立视频 Studio
出现第二个真实消费者后，再决定是否提取进共享 package。
